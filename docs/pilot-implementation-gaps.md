# Single-site pilot implementation status

This document reflects the current working tree at HEAD `35af770bce3859817dff2e666d419fb1f11586f0`. Changes are uncommitted. No production-readiness claim is made.

## Implemented in the current workspace

- Tenant/site-scoped access, OIDC API token verification, authenticated actor identity and backend role checks. Browser OIDC Authorization Code + PKCE, identity/scope display, logout and expiry handling are implemented; a configured IdP/browser flow has not been exercised.
- Response episodes, assignments, acknowledgement, response, SOP steps, resolution, handover, idempotency and expected-version conflict checks.
- SLA policy snapshots and durable breach records. A provider-neutral notification adapter records queued/delivered/failed attempts, retries and human acknowledgement separately; local development is no-send. Each breach currently creates one notification level. Configurable timed escalation levels and an approved external provider are not implemented.
- Pinned async PDF/ZIP exports, access checks on generation/download, expiry and audit logging; JSON/CSV remain. ZIP media is hash-checked and missing media is represented in the manifest.
- Stream/video/recording/evidence component health, frame quality signals, freeze debounce, maintenance windows, gap/lag/latency metrics and readiness/metrics endpoints.
- Restricted production Compose profile, private service networks, MQTT auth/ACL configuration hooks, Frigate token configuration, DB bootstrap roles and migration service.
- Demo/replay banner, overview dashboard and deterministic canonical mock event pipeline.

## Partial or outstanding

- Notification levels are not configurable; external email/SMS/pager integration and real escalation routing are intentionally absent.
- UI has not been compiled or tested with configured OIDC provider; provider registration, MFA, callback/logout behavior, key rotation and revocation need integration testing.
- PDF is generated by an internal minimal PDF writer and needs rendering/reader validation. Export tests need to confirm missing media behavior, expired/held media policy, output sanitization and stable pinned contents on this runtime.
- Frigate health and recording probes have not been run against an authenticated live source. Probe freshness/WAN simulation, capacity and metrics semantics need pilot validation.
- Compose profile and DB role permissions have only been designed/edited; Docker/PostgreSQL execution is blocked. `docker-entrypoint-initdb.d` runs only for an empty database volume. Existing databases need a reviewed migration procedure.
- E10 review packaging is incomplete. Current scripts seed the canonical mock pipeline, but do not establish a fixed scenario clock/IDs, versioned fixture manifest, isolated reset namespace or all ten review scenarios.
- Backup/restore, key recovery, broker/API/database restarts, live Frigate/MQTT ingestion, authenticated browser workflow, and tenant-negative PostgreSQL tests need an available runtime.

## Explicit decision-support limitation

Detection, behaviour and cross-camera correlation are signals for human review, not proof of identity, criminal activity or wrongdoing. Cross-camera narratives must use “Correlated movement across cameras”; do not claim “Same person confirmed” or “Identity verified.”
